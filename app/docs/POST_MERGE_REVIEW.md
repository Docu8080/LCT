# Повторная проверка после слияния

11 октября 2026. PR #1 слит в main: `e920a4e6f114d918e17e049d9291b37cb946aae0`. Проверяемые 22 файла сверены по Git blob SHA с этим коммитом; ресурсы интерфейса восстановлены из того же дерева. Слияние прошло CI. После него отдельно проверены реализация и пограничные сценарии.

## Найдено и исправлено

| Проблема | Воспроизведение и исправление |
|---|---|
| Сеанс мог жить дольше демо-сценария | При оставшихся 20 секундах сценария создавался сеанс на следующие 24 часа. Теперь срок сеанса/cookie ограничен сроком пары, а общий current проверяет срок пары на каждом защищённом запросе. |
| Просроченная cookie мешала входу в демо | Действующая пара с истёкшим сеансом возвращала 401. Теперь 401 допускает новый сеанс по cookie пары; неверный CSRF действующего сеанса по-прежнему отклоняется. |
| Истёкшая попытка обходила 30-дневную паузу | После таймера разрешалась новая попытка того же грейда. Общая eligibility учитывает завершённые, истёкшие и активные попытки с истёкшим дедлайном. Сохранение ответов после срока остаётся запрещено. |
| Смена роли очищала контекст ошибки сохранения | При saveFailed=true demoLogin отправлял запрос и очищал attempt. Общий waitForSavedAnswers теперь используется сменой роли, выходом и завершением теста. Подтверждённый сброс очищает сценарий и ошибку. |
| Повреждён русский текст входного HTML | Предыдущее обновление версии кеша читало UTF-8 с кодировкой Windows по умолчанию. Восстановлены title, description и начальный текст загрузки из исходного UTF-8; добавлен HTTP-тест. |

Три новых API-теста сначала упали на слитом коде. JavaScript-проверка зафиксировала запрос смены роли после ошибки сохранения. Затем исправления прошли проверки. Тест публичных страниц теперь запускается независимо от других тестовых модулей.

## Логика и структура

- Авторизация, роли, владелец, срок пары и CSRF сходятся в current/candidate/employer. Профиль и PDF используют общий view_candidate; контакты требуют отдельного grant. Проверена изоляция каталога, деталей, вакансий, приглашений, откликов и заданий.
- SQLite-операции транзакционны. Сброс создаёт новый сценарий до удаления прежнего и откатывается целиком при ошибке. Миграции не приписывают старым пользователям согласия; проверки удаления связанных записей сохранены.
- assessment.py и matching.py разделяют оценивание и ранжирование; формулы не менялись. Неудачный тест сохраняет ранее присвоенную категорию. Пропущенные ответы неверные; ключи и параметры сложности не выдаются в вопросы API.
- resume.py разбирает PDF в ограниченном отдельном процессе. Preview не сохраняет файл, не публикует профиль и не присваивает категорию; применение к анкете и сохранение отдельные.
- В браузере общий API-клиент и единая проверка автосохранения. Аудит теперь проверяет фактическую загрузку кабинета: ошибка API не считается успешно проверенным экраном.
- run.sh учитывает изменение lock-файла; Docker включает resume.py. Дополнительной сборки фронтенда и npm-зависимостей нет. Разбиение большого server.py на новые слои для этих исправлений не потребовалось.
