# Соответствие официальному ТЗ

Источник: `../../materials/official/ФСП/ФСП спец. трек ТЗ.pdf`, 9 страниц включая обложку. Инструкции из файла использованы как требования к продукту, а не как разрешение публиковать или сдавать что-либо от имени пользователя.

| Требование | Статус и реализация |
|---|---|
| Независимая платформа обратного найма | Работодатель ищет профиль и приглашает адресно; внешние агрегаторы не парсятся |
| Две роли, регистрация, подтверждение почты | Реализовано. В демо код на экране; для доставки предусмотрен SMTP, не проверен |
| Опрос отрасль / специализация / уровень | Анкета включает отрасль, Backend/Frontend и самооценку Junior/Middle/Senior |
| Подтверждённая категория после теста | Реализовано по каждой специализации; категории seed-данных вымышленные |
| Не понижать автоматически после неудачи | Ранее подтверждённая категория сохраняется; проверено тестом |
| Ограничение частоты изменения категории, исключения | 90 дней; следующий уровень после уверенного результата; ниже после неудачи. Повтор того же теста 30 дней |
| Сопоставимые тесты и устойчивость к утечкам | План 5×3, параметрические шаблоны, серверные ключи, IRT/EAP. Сопоставимость экспертная; полноценный античит и калибровка отсутствуют |
| Поиск по потребности с фильтрами | Категория/специализация/стек/зарплата/формат потребности, поиск по опыту и навыкам, ФСП; параметры в URL |
| Мягкое ранжирование и объяснение | Семь факторов, частичная смежность, разложение вклада, нейтральный сигнал при отсутствии ФСП |
| Личное приглашение, зарплатная вилка в ₽ | Обязательные описание, границы зарплаты, формат и контакт компании; отдельный адресат |
| Контакты скрыты до принятия/отклика | Серверное разрешение конкретной компании, отдельный checkbox; PDF соблюдает тот же доступ |
| Участник видит своё, компания — своё | Проверка владельца записей и роли в API; проверена в тестах |
| Резюме формой или разбором PDF | Реализована форма. Разбор входного PDF не реализован; ТЗ допускает альтернативу |
| Стандартизированный PDF | Генерируется из профиля и категорий; кириллица, собственный/скрытый варианты |
| Согласия, публикация и приватность ФСП | Обработка отдельно от публикации и контактов; новый профиль скрыт по умолчанию; ФСП можно скрыть/отвязать |
| Связь с ID ФСП и обработка отсутствия истории | Только явно обозначенный демо-адаптер; код связывания, 6 ID. Реальных API организаторы не дали |
| Собственные данные и валидация | Seed-профили, параметрические формы, набор 150 профилей × 40 потребностей, отдельная синтетическая рубрика и 720 симуляций; методика и ограничения открыты |
| Короткие регулярные задания (дополнительно) | Раз в неделю при чтении кабинета, категория и тема, ручная открытая рубрика и обратная связь |
| Публикация вакансии / самоотклик (дополнительно) | Потребность может быть вакансией, отклик с отдельным согласием |
| Документация, воспроизводимый запуск и OpenAPI | README, архитектура, модели, проверки, сценарий, OpenAPI и локальная страница API |
| Docker (желательно) | Файлы подготовлены; Docker-сборка не проверена — daemon не запущен |
| Публичный демонстрационный стенд | Пока только локальный сервер; внешний деплой не запрошен |
| Ссылка на репозиторий, презентацию и документацию для сдачи | Исходники, документы, ТЗ и шаблон подготовлены для передачи в [Docu8080/LTN](https://github.com/Docu8080/LTN). Презентация и конкурсная сдача не выполнены |

Презентационный шаблон сохранён отдельно и не менялся. Обязательные слайды 7–11 остаются в исходном дизайне и структуре. Для завершения конкурсной сдачи потребуется отдельно оформить презентацию и разместить разрешённые пользователем артефакты.
