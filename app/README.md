# ФСП Таланты

Рабочий локальный MVP цифровой платформы обратного найма по ТЗ специального трека ФСП. Участник заполняет профиль и подтверждает категорию. Компания описывает потребность, получает объяснимый список кандидатов и отправляет личное приглашение с зарплатной вилкой. Контакты открываются только по отдельному разрешению участника.

Проект написан самостоятельно. Код исследованных репозиториев сюда не перенесён. Карта передачи и задачи продолжения — в [HANDOFF.md](../HANDOFF.md).

## Быстрый запуск

Требуется Python 3.11–3.13 и интернет только для первого скачивания зависимостей. Проверено на macOS с Python 3.13.1. Сборка фронтенда, Node.js и внешняя БД для запуска не нужны.

```sh
cd app
./run.sh
```

Из этой папки можно сразу выполнить `./run.sh`. При первом запуске создаются `.venv-runtime`, SQLite и синтетические профили. `requirements.lock.txt` фиксирует полный набор версий; `requirements.txt` — прямые зависимости. Окружение и локальная БД в репозиторий не входят.

Открыть [приложение](http://127.0.0.1:8080), [документацию API](http://127.0.0.1:8080/docs) или [OpenAPI JSON](http://127.0.0.1:8080/openapi.json). Остановка — Ctrl+C в терминале сервера. Другой порт: `PORT=8081 ./run.sh`.

Для разработки:

```sh
.venv-runtime/bin/python -X pycache_prefix=data/python-cache -m uvicorn server:app --host 127.0.0.1 --port 8080 --reload
```

|---|---|---|
| `candidate@demo.ru` | Профиль Middle, ФСП, входящее приглашение | `Demo2026!` |
| `fresh@demo.ru` | Первый тест, публикация профиля | `Demo2026!` |
| `hr@demo.ru` | Подбор, потребности, приглашения, проверка задач | `Demo2026!` |
| `team@demo.ru` | Изоляция второй компании | `Demo2026!` |

Кнопки на странице входа создают **личный сценарий браузера**: подтверждённого участника, нового участника и компанию. В кабинете доступны «Сменить роль» и «Начать заново». Каталог, вакансии, приглашения, контакты и задания изолированы между сценариями. При выходе сценарий сохраняется, при сбросе удаляются только его данные. Срок сценария — 7 дней; просроченные сценарии очищаются при следующем создании демо. Режим доступен только при `FSP_DEMO=1`.

Аккаунты из таблицы доступны через обычную форму входа и остаются общими; для независимой демонстрации используйте демо-кнопки. Парольные вход и удаление для личных синтетических аккаунтов недоступны: вместо них используется cookie сценария и его сброс. База сохраняется между перезапусками. Все демо-люди, компании, контакты, категории и достижения вымышленные. Первый seed создаётся только для пустой базы.

## Что работает

- Баннер необходимых cookie без аналитики и рекламы; отдельные незаполненные подтверждения условий, обработки данных и возраста 18+ при регистрации. Новые профили и достижения скрыты, пока пользователь явно не включит их.
- Раздел управления данными для обеих ролей: сохранённые версии и даты согласий, отказ от рекламных рассылок, отзыв согласия и удаление аккаунта с паролем. Для деактивированного аккаунта доступно отдельное удаление на `/deletion`. Это удаление записей рабочей SQLite, не резервных копий или внешних PDF.
- Полностью обновлённый адаптивный интерфейс: главная, вход, кабинеты участника и компании, паспорт навыков, каталог и объяснение подбора. Единый визуальный слой в `static/style.css`, без внешних шрифтов и библиотек.
- Публичные страницы `/terms`, `/privacy`, `/cookies`, `/refunds`, `/consent`, `/operator`, `/deletion`, `/licenses`, `/help`, `/accessibility`, поиск по справке и оформленные состояния 403/404. Неизвестные серверные адреса возвращают HTML со статусом 404, неизвестные API — JSON 404. Юридические тексты описывают локальное демо; перед публичным запуском нужны сведения об операторе и утверждённые правила обработки данных.
- Регистрация кандидата и работодателя, подтверждение email шестизначным кодом, повторная отправка кода, серверные сеансы и выход.
- Анкета: отрасль ИТ, специализация, самооценка уровня, опыт, стек, гибкие навыки, командная роль, зарплата, формат и город; стандартизированный PDF с кириллицей.
- PDF-резюме предзаполняет известные навыки, телефон, Telegram и явно подписанные ФИО/стаж после редактируемого preview. Только текстовые PDF до 2 МБ и 10 страниц; OCR/DOCX нет. Файл не сохраняется, категория и публикация не меняются; анкету сохраняет пользователь.
- Несколько подтверждённых категорий по специализациям Backend/Frontend и уровням Junior/Middle/Senior.
- Тест из 15 параметрических заданий, три области, 30 минут, серверное автосохранение, версия ответов и восстановление попытки после перезагрузки.
- IRT/EAP: результат с θ, стандартной ошибкой, уверенностью решения и темами для развития. Сложность пока экспертная, а не откалиброванная на реальных кандидатах.
- Неудачная попытка сохраняет ранее подтверждённую категорию. Повтор того же теста через 30 дней; смена категории через 90 дней; уверенный результат открывает следующий грейд на 14 дней; после неудачи разрешена проба ниже.
- Подбор по потребности компании, поиск по навыкам и опыту, фильтр достижений ФСП, сохранение параметров в адресе, ранжирование и разложение рейтинга по семи факторам.
- В поиске все слова обязательны: `Python SQL`, `SQL, Python` и `Python; SQL` ищут одинаково, без учёта регистра. Поиск не использует имя и контакты. Это текстовый фильтр без LLM.
- Именное приглашение кандидату: описание, вилка в рублях, формат и способ связи; просмотр, принятие, отказ, отзыв работодателем и истечение через 14 дней.
- Раздельные настройки обработки данных, публикации профиля, видимости ФСП и контактов для конкретной компании. Отзыв доступа закрывает контакты и PDF. Повтор старого принятия не восстанавливает отозванное разрешение.
- Короткие задания работодателей: назначение подходящей категории не чаще раза в неделю, приоритет доступной темы с меньшим баллом теста, дедлайн, ответ, ручная рубрика 0–2 по трём критериям и обратная связь.
- Публикация вакансий из потребностей и самостоятельные отклики с отдельным согласием на контакты.
- Уведомления внутри кабинета, журнал значимых действий, API-документация без внешних CDN.

## Настройка

`.env.example` содержит список переменных. Приложение читает **окружение процесса**, не подгружает `.env` автоматически.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `FSP_DEMO` | `1` | Синтетические данные и показ демо-кодов |
| `FSP_DATABASE` | `data/fsp.sqlite3` | Файл SQLite |
| `FSP_COOKIE_SECURE` | `0` | `1` для HTTPS |
| `FSP_SMTP_HOST` | не задана | SMTP-сервер |
| `FSP_SMTP_PORT` | `587` | STARTTLS-порт |
| `FSP_SMTP_FROM` | `noreply@example.org` | Отправитель |
| `FSP_SMTP_USER`, `FSP_SMTP_PASSWORD` | не заданы | SMTP-авторизация |

В локальном демо письмо не отправляется: код отображается на экране и действует 15 минут. При `FSP_DEMO=0` регистрация требует SMTP. Чтобы начать с чистой недемонстрационной базы, используйте **новый путь** `FSP_DATABASE`, иначе ранее созданные демо-аккаунты сохранятся. Внешний сервис ФСП не подключён: связывание ID в этом режиме возвращает 503, а не вымышленные «проверенные» данные.

PDF использует комплектный свободно распространяемый DejaVu Sans 2.37 (`fonts/DejaVuSans.ttf`); исходная лицензия сохранена в `fonts/LICENSE-DejaVu.txt` и на странице `/licenses`. Arial не используется. Интерфейс использует системные шрифты устройства, без внешних загрузок.

Реквизиты задаются только владельцем сервера через `FSP_OPERATOR_NAME`, `FSP_OPERATOR_INN`, `FSP_OPERATOR_OGRN`, `FSP_OPERATOR_ADDRESS`, `FSP_OPERATOR_EMAIL`. Если значения не заданы, `/operator` явно показывает это. Данные старых аккаунтов сохраняются; отсутствующие даты согласий, подтверждения возраста и условий не подменяются вымышленными записями.

Чек-лист всех 20 пунктов пользователя и ограничения: [docs/PRIVACY_AND_ACCESSIBILITY.md](docs/PRIVACY_AND_ACCESSIBILITY.md).

## Проверка

```sh
.venv-runtime/bin/python -X pycache_prefix=data/python-cache -m unittest discover -s tests -v
.venv-runtime/bin/python -X pycache_prefix=data/python-cache tests/validate_models.py
```

24 теста проверяют роли и принадлежность данных, CSRF/Origin, согласия и скрытые контакты, PDF, автосохранение и конфликты версий, результат и запрет принудительного понижения, проверку почты, зарплатные границы, дубликаты приглашений, оценку заданий и HTTP-маршруты публичных страниц/404; новые проверки также охватывают возраст/условия, приватные значения по умолчанию, миграцию старых записей, отказ от рассылок и удаление для обеих ролей с проверкой пароля/CSRF/Origin. Генератор дополнительно проверяется выполнением Python и SQL для 120 форм; 450 JavaScript-заданий проверяются отдельным `node tests/verify_frontend.mjs` при наличии Node.js; EAP — на монотонность и крайние ответы.

В `docs/validation_results.json` сохранены результаты симуляции 720 тестовых попыток и 40 поисковых запросов к 150 синтетическим профилям. Данные и отдельная рубрика релевантности — в `docs/validation_dataset.json`. Это инженерная проверка, **не оценка качества реальных кандидатов или найма**. Методика и ограничения — [docs/VALIDATION.md](docs/VALIDATION.md).

После обновления дизайна браузером проверены главная, подбор, объяснение рейтинга, вход, мобильный обзор участника, профиль и меню. Для добавленных затем privacy-экранов повторный визуальный проход ещё нужен. Подробности и ограничения проверки — [docs/FRONTEND_QA.md](docs/FRONTEND_QA.md).

## Docker

```sh
docker compose up --build
```

Один контейнер, локальный порт 8080, непривилегированный пользователь, healthcheck и сохраняемый volume БД. Перед Docker-запуском остановите локальный сервер на том же порту. Docker-образ собран и проверен в [CI b9f3171](https://github.com/Docu8080/LTN/actions/runs/38163844052): здоровье, две роли, PDF со шрифтом, изоляция каталога и OpenAPI. Этот smoke не заменяет проверку вашего внешнего HTTPS-стенда и восстановления volume из резервной копии.

## Структура и ограничения

[Архитектура и модель данных](docs/ARCHITECTURE.md), [соответствие ТЗ](docs/TZ_COVERAGE.md), [демонстрационный сценарий](docs/DEMO.md), [контракт OpenAPI](docs/openapi.json).

Это локальный MVP. Реальные реестр и авторизация ФСП, эмпирическая калибровка банка, восстановление пароля, фоновая рассылка уведомлений, модерация компаний и публичный HTTPS-деплой не реализованы. Задания назначаются при открытии кабинета, срок приглашений обновляется при чтении списка. Нет обещаний производственной готовности или реальной верификации синтетических достижений.

Официальные материалы сохранены отдельно в `../materials/official/ФСП/`. Шаблон презентации не изменён; слайды 7–11 требуют сохранения дизайна и структуры. Срок в объявлении: 11 октября до 23:59 МСК. Презентация и внешняя сдача решения в этот проектный этап не входят.
