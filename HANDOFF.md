# Передача LTN следующему разработчику

Продукт — **ФСП Таланты**, локальный MVP специального трека ФСП. Начните с [README приложения](app/README.md), [полного ТЗ](materials/official/ФСП/ФСП%20спец.%20трек%20ТЗ.pdf) и [карты соответствия ТЗ](app/docs/TZ_COVERAGE.md). Этот документ описывает состояние исходников на 11 октября 2026 года; он не подтверждает конкурсную сдачу или запуск публичного сервиса.

## Запуск и проверка

Требуется Python 3.11–3.13. Первый запуск скачивает зависимости из `requirements.lock.txt`; после установки сервер работает локально без Node.js и внешней БД.

```sh
cd app
./run.sh
```

Адрес: `http://127.0.0.1:8080`; API: `/docs` и `/openapi.json`. Скрипт запуска использует `.venv-runtime`, создаёт SQLite и при включённом демо заполняет пустую БД синтетическими профилями. Данные сохраняются между перезапусками. Демо-пароль `Demo2026!` опубликован намеренно и относится только к вымышленным аккаунтам из [README](app/README.md).

Из папки `app/`:

```sh
.venv-runtime/bin/python -X pycache_prefix=data/python-cache -m unittest discover -s tests -v
.venv-runtime/bin/python -X pycache_prefix=data/python-cache tests/validate_models.py
```

Для дополнительных проверок JavaScript нужен Node.js:

```sh
node --check static/app.js
node --check static/pages.js
node --check static/privacy.js
node tests/verify_frontend.mjs
```

Последний зафиксированный прогон — **24 успешных теста**. Они проверяют роли и владельцев записей, CSRF/Origin, регистрацию и согласия, приватность, PDF, попытки тестирования, приглашения, задания, миграции и удаление аккаунтов. Модельные проверки описаны отдельно в [VALIDATION.md](app/docs/VALIDATION.md). Это синтетическая проверка свойств, а не доказательство качества найма.

Граница backend/frontend простая: браузер обращается к `/api/*`, сеанс хранится в HttpOnly cookie, изменяющие защищённые операции требуют CSRF-токен. Код остаётся одним приложением с SQLite; отдельной очереди, фронтенд-сборки, LLM и внешнего агрегатора вакансий нет. Подробности схемы и состояний — в [ARCHITECTURE.md](app/docs/ARCHITECTURE.md).

- Кабинеты участника и компании, регистрация с кодом email, анкета и PDF-профиль.
- Категории Backend/Frontend × Junior/Middle/Senior, параметрический тест из 15 заданий с серверным автосохранением, оценка IRT/EAP и правила повторных попыток.
- Потребности компании, каталог, объяснимый подбор по семи факторам, личные приглашения, вакансии и отклики.
- Короткие задания по категории и слабой теме, ручная рубрика и обратная связь, уведомления внутри кабинета.
- Отдельные решения о публикации профиля, видимости ФСП и открытии контактов конкретной компании; PDF соблюдает разрешения.
- Адаптивный интерфейс, собственная иконка, справка, страницы 403/404 и юридические разделы.
- Незаполненные согласия на обработку данных, условия и возраст 18+, запись версий и дат, отказ от рассылок, отзыв согласия и удаление для обеих ролей.

Новые профили скрыты по умолчанию. Не ослабляйте проверку роли/владельца, отдельное согласие на контакты, CSRF и проверку пароля при удалении. Старым аккаунтам приложение не приписывает отсутствующие даты согласий или подтверждение возраста.

## Демо и реальные данные

Приложение читает **переменные окружения процесса**. `.env.example` — справочник; `.env` автоматически не загружается. Не добавляйте реальные секреты в Git.

`FSP_DEMO=1` — режим по умолчанию: синтетические данные, демонстрационные коды email и шесть вымышленных ID ФСП. Эти достижения не подтверждены реальным реестром. При `FSP_DEMO=0` нужны настройки SMTP для регистрации, а связь с ФСП возвращает 503 до появления реальной интеграции.

Для отдельной недемонстрационной БД задайте **новый путь**, не используйте уже заполненный демо-файл:

```sh
export FSP_DEMO=0
export FSP_DATABASE=/absolute/path/to/new/fsp.sqlite3
```

До регистрации задайте `FSP_SMTP_HOST`, `FSP_SMTP_PORT`, `FSP_SMTP_FROM` и необходимые учётные данные SMTP в приватном окружении. Для HTTPS включите `FSP_COOKIE_SECURE=1`. Эти настройки описывают переключение режима, а не готовый production-процесс.

Публичные реквизиты заполняет владелец сервиса: `FSP_OPERATOR_NAME`, `FSP_OPERATOR_INN`, `FSP_OPERATOR_OGRN`, `FSP_OPERATOR_ADDRESS`, `FSP_OPERATOR_EMAIL`. Пока они не предоставлены, `/operator` показывает отсутствие сведений. В эти поля нельзя помещать секреты: они доступны через `/api/legal/config`.

## Приоритеты продолжения

1. **Завершить конкурсные артефакты.** Презентация ещё не подготовлена, внешний стенд и отправка решения на платформу не выполнены. Официальные слайды 7–11 обязательны; сохраните их дизайн и структуру. Дедлайн из объявления: 11 октября 2026 года, 23:59 МСК. Адрес платформы сдачи не предоставлен.
2. **Согласовать реальную интеграцию ФСП.** Заменить демо-реестр и код владения на настоящий согласованный API/процесс. Официальных готовых датасетов и API в полученных материалах нет; собственные данные — `app/docs/validation_dataset.json` и seed в `server.py`.
3. **Подготовить аккаунты и операционные сценарии.** Восстановление пароля и модерация компаний отсутствуют. Почтовый транспорт предусмотрен, но реальный провайдер и доставка должны быть настроены и проверены. Назначение заданий и истечение приглашений сейчас выполняются при чтении кабинета, а не фоновым планировщиком.
4. **Проверить оценивание на реальных данных.** Сложность заданий и пороги экспертные; требуется эмпирическая калибровка IRT, проверка сопоставимости форм и политика защиты от утечек. Не обещайте независимую или точную оценку кандидатов на основании текущей симуляции.
5. **Подготовить эксплуатацию.** HTTPS, миграции и резервное копирование, восстановление, мониторинг, проверка нагрузки и безопасности. Для роста нагрузки оценить PostgreSQL и фоновые процессы. Сейчас приложение использует SQLite и сериализующие транзакции.
6. **Утвердить юридические условия.** Реальные реквизиты, цели/сроки хранения, обработчики данных и правила резервных копий/выгрузок должны быть определены владельцем. Тексты описывают бесплатный локальный демо-сервис; платежи не реализованы. Удаление рабочей SQLite не стирает резервные копии и ранее скачанные PDF. Регистрация рассчитана на 18+, это заявление пользователя, не проверка документа.
7. **Завершить проверку интерфейса.** Проверены основные desktop/mobile-сценарии прежнего этапа; новые privacy-экраны требуют повторного визуального и клавиатурного прохода, проверки скринридером, разных браузеров и всех состояний контраста. Docker-сборка пока не проверена. Полный аудит WCAG и производственная готовность не заявлены.
