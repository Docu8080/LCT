Новых ошибок приложения в проверенных сценариях не обнаружено. Ранее исправленные обновление статуса просмотра и появление нового приглашения продолжают проходить браузерную проверку.

## Что добавлено

Две проверки в существующий браузерный сценарий:

1. Связывание `FSP-DEMO-001`: неверный шестизначный код отклоняется и отображается в форме; правильный код после ошибки успешно подтверждает связь; отвязка удаляет ID из серверного профиля.
2. Создание потребности с верхней зарплатой ниже нижней: API отклоняет форму, запись не появляется; после исправления зарплаты сохранение проходит.

Обновлены JSON-результат и указатели на актуальную проверку. Новый runtime-код не требовался. Эти сценарии автоматически выполняются существующим GitHub Actions на собранном Docker-образе вместе с HTTP-smoke.

## Воспроизведение и границы

Из `app`: `python -m unittest discover -s tests -v`, `python tests/validate_models.py --check`, `node tests/check_save_state.mjs`, `node tests/verify_frontend.mjs`. Для браузера запустите отдельную локальную демо-базу и выполните `node tests/audit_contrast.mjs` с Node.js 22+ и Chrome. При необходимости задайте `FSP_BASE_URL` и `CHROME_PATH`. Скрипт создаёт/удаляет собственные аккаунты и сбрасывает своё личное демо; не запускайте его на рабочей базе.

Проверка относится к локальному MVP и синтетическим данным. Реальная SMTP-доставка, API ФСП, внешний HTTPS-стенд, другие браузеры, нагрузка и полный WCAG в этот проход не входили. Симуляция моделей не доказывает качество реального найма.
