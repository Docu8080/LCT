## Проверенные цепочки

1. Регистрация участника и работодателя, независимые подтверждения, локальный код email, выход и повторный вход паролем. Новый профиль остаётся скрытым. Удаление каждого созданного аккаунта завершает его сеанс.
2. Сохранение анкеты, контактов и любого формата работы; повторное чтение после перезагрузки. PDF загружается в настоящий preview, найденные поля применяются к редактируемой форме.
3. Старт Junior-теста, изменение ответа, серверное сохранение и восстановление после перезагрузки. При отключении сети UI показывает несохранённый ответ и блокирует переход. После подключения и изменения ответа сохранение возобновляется. Завершение и история результата сохраняются в БД; неполная неуспешная попытка не присваивает категорию.
4. Создание и публикация потребности, поиск по «Python SQL», скрытые контакты до согласия. Отзыв исходного активного приглашения, создание нового, статус просмотра, принятие с отдельным checkbox, открытие контактов работодателю и отзыв разрешения участником.
5. Отклик на созданную вакансию; он сохраняется после перезагрузки, отображается работодателю и открывает контакты по отдельному согласию.
6. Создание практического задания, ответ на назначенное задание, ручная оценка работодателя по рубрике 2/2/1. Участник видит 83% и комментарий; данные сохраняются после перезагрузки, уведомления отмечаются прочитанными.
7. Скрытие/публикация профиля реально удаляет/возвращает кандидата в подборе работодателя. Переключение ролей и сброс личного демо, выключенные демо-кнопки и PDF-контракт API также проверяются.

Локальный итог: 38 unittest, 450 исполняемых JavaScript-ответов, проверки очереди сохранения и воспроизводимости модельного отчёта проходят. Ruff и Prettier проходят. ## Повторение и CI

На **отдельной локальной демо-базе** запустите приложение с `FSP_DEMO=1`, затем из `app` выполните `node tests/audit_contrast.mjs`. Нужны Node.js 22+ и Chrome. `FSP_BASE_URL` меняет адрес сервера, `CHROME_PATH` — исполняемый файл браузера; `CHROME_NO_SANDBOX=1` используется только для ограниченного тестового окружения. Скрипт создаёт и удаляет собственные тестовые аккаунты и сбрасывает личное демо. Повторные быстрые запуски могут попасть под нормальный лимит создания сценариев; дождитесь минуты или перезапустите отдельный тестовый сервер.

Тот же браузерный проход добавлен в GitHub Actions после Docker-сборки и HTTP-smoke, с `FSP_BASE_URL=http://127.0.0.1:18080`. Таким образом проверки используют именно упакованные статические файлы, API и SQLite, а не отдельные заглушки. Тесты не требуют Playwright/Selenium или новых runtime-зависимостей.

Браузерный код: [browser_integration.mjs](../app/tests/browser_integration.mjs), запуск и аудит: [audit_contrast.mjs](../app/tests/audit_contrast.mjs), локальный результат: [contrast_browser_results.json](../app/docs/contrast_browser_results.json).

## Границы вывода

Проход проверяет локальный MVP на синтетических данных в Chrome. SMTP-доставка, настоящее API ФСП, внешний HTTPS-прокси, восстановление резервной копии, нагрузка, другие браузеры и полный WCAG остаются отдельными задачами. Расчёт проходного теста и категорий проверяют серверные тесты; браузерная попытка намеренно неполная. Контраст считается только для поддерживаемых сплошных фонов; пропущенные состояния и наложения требуют визуальной проверки. Модельные метрики остаются симуляцией, а не доказательством качества найма.
