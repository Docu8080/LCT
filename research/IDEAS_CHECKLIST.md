# Идеи для собственного проекта

Основано на [полной выжимке](FSP_REPOSITORIES_DIGEST.md), 8 октября 2026. Это список идей, а не уже реализованные изменения.

## Первый сквозной MVP

- [ ] Регистрация по email, роли candidate/employer, подтверждение почты.
- [ ] Профиль: стек, стаж, специализация, заявленный грейд, формат, зарплата, приватность.
- [ ] Серверная тестовая попытка: задания, таймер, автосохранение, восстановление, конфликт версий.
- [ ] Подтверждённая категория и явный статус неподтверждённого грейда.
- [ ] Потребность работодателя и объяснимая подборка по категории, навыкам и условиям.
- [ ] Приглашение конкретному кандидату с описанием и обязательной вилкой.
- [ ] Просмотр/принятие/отклонение/отзыв, дедлайн, защита от дублей.
- [ ] Адресное согласие на контакты и отзыв; общая политика для API/PDF.
- [ ] Демо-реестр ФСП с явной маркировкой и заменяемым адаптером.
- [ ] Smoke полного пути и проверка прав на чужие объекты.

## После работающего пути

- [ ] Несколько независимых категорий и кулдаун каждой.
- [ ] Параметрические шаблоны, blueprint, IRT/EAP, версии банка и калибровки.
- [ ] Адресные задачи по потребности и слабой компетенции, рубрика, свежесть сигнала.
- [ ] Серверные уведомления, просмотр на нескольких устройствах, outbox.
- [ ] Подписанный паспорт с QR, сроком, источником данных и отзывом.
- [ ] PostgreSQL RLS, отдельная роль БД и реальные PostgreSQL-тесты.
- [ ] PDF/DOCX-импорт и стандартный PDF-профиль с подходящим шрифтом.
- [ ] RU/EN для всей цепочки, включая серверные объяснения и задания.

## Отдельные эксперименты

- [ ] CAT: 10–18 вопросов, информация около порога, randomesque, квоты тем.
- [ ] Test–retest, D/r_pb, эквивалентность форм, ошибки/ложные сигналы.
- [ ] Бенчмарк подбора с базовой формулой, P@K/NDCG/MRR и отложенными данными.
- [ ] Пилот реальных кандидатов до обещаний качества.
- [ ] LLM для разбора текста/второго мнения, обезличивание, схема, лимит и fallback.

## Решения, которые нужно принять явно

- [ ] Как влияет отсутствие ФСП: 0, нейтральная база или отсутствие фактора?
- [ ] Какова единая шкала грейда и отдельные правила пересдачи/повышения?
- [ ] Как учитываются пропущенные ответы и прерванная попытка?
- [ ] Какой доступ остаётся после отзыва согласия, включая PDF и интеграции?
- [ ] Какие возможности — мок, концепция, код или реально проверенный сценарий?
- [ ] Какие идеи реализуем самостоятельно и какой код имеет подтверждённую лицензию?
