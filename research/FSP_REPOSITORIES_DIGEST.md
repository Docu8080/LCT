Дата фиксации: **8 октября 2026 года**. В исходном списке SergeLyamin/fsp-talent указан дважды; разобран один раз. Цель — сохранить существенные продуктовые механики, архитектуру, алгоритмы, ограничения и материалы для собственного проекта.

При исследовании локально сохранены **полные ZIP-снимки на конкретных коммитах**. В LTN переданы эта выжимка, список идей, манифест и доказательства; полные сторонние исходники и архивы в репозиторий LTN не включены. Ссылки на документы и реализации ведут на закреплённые коммиты исходных репозиториев. История Git, другие ветки, issues, PR и внешние сайты в снимки не входят. Никаких форков, звёзд, подписок, PR, комментариев или изменений на GitHub при исследовании не создавалось. Загрузка выполнялась публичными запросами без авторизации. Обычные обращения к GitHub могут учитываться сервисом; абсолютная невидимость сетевого чтения не предполагается.

Выводы основаны на README, документации и выборочном чтении значимых реализаций. **Наличие кода ≠ подтверждённая работоспособность:** приложения, тесты, деплой и нагрузочные сценарии в этом исследовании не запускались. Числа из авторских отчётов явно отмечены как заявленные.

## 2. miliantr/fsp-talent — механики оценки и объяснимого подбора

[Репозиторий](https://github.com/miliantr/fsp-talent). Снимок: `906a559c7ee0e0fa016a6bad411a24752e5588c2`.

**Продукт.** Обратный найм, регистрация с подтверждением почты, профиль и импорт PDF-резюме, потребности работодателя, подборки, приглашения, вакансии и отклики, PDF-профиль, короткие задания, жалобы. Несколько категорий кандидата, выбор основной, отдельный кулдаун каждой категории. Грейд без теста обозначается как неподтверждённый. Эти уточнения зафиксированы в [карте ответов заказчика](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/docs/clarifications.md); это пересказ ответов командой, а не независимо проверенный документ организаторов.

**Тестирование.** По документации: 252 задания, 25 параметрических семейств, 4 специализации и 21 компетенция. Вариант собирается по blueprint, результат оценивается IRT 3PL/EAP с оценкой неопределённости. Есть проверка согласованности ответов, сравнение статических и генерируемых вопросов, сигналы поведения и подтверждающая форма. Повтор — через 30 дней; смена грейда — раз в 90 дней; после неудачи можно тестироваться ниже, после уверенного результата — выше. Детали: [testing.md](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/docs/testing.md), [реализация EAP](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/backend/app/services/testing/irt.py).

**Подбор.** Девять компонентов: стек, грейд, уровень теста относительно потребности, специализация, ФСП, актуальность, зарплата, опыт, формат. Граф близких технологий; подтверждённый навык весит больше заявленного. Для отсутствующей истории ФСП предусмотрена нейтральная база; отсутствующие применимые данные не следует автоматически превращать в штраф. Есть мягкое сочетание обязательных навыков, разложение итогового процента, сравнение A/B, сохранённый снимок подборки. Код движка независим от БД и используется также в бенчмарке. Источники: [matching.md](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/docs/matching.md), [engine.py](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/backend/app/services/matching/engine.py).

**Адресные задания.** Назначение учитывает соответствие категории/грейду, попадание кандидата в подборку конкретной потребности, слабо подтверждённую компетенцию, новизну и нагрузку на проверку. Уже предложенные задания не выдаются снова; число предложений ограничено. Автопроверка числового/текстового ответа или предварительная оценка плюс рубрика работодателя. Результат освежает сигнал в подборе; грейд определяется отдельным тестом. Источник: [tasks_service.py](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/backend/app/services/tasks_service.py).

**Архитектура.** React 19 + TypeScript + Vite; FastAPI, SQLAlchemy 2, Alembic; PostgreSQL, локально SQLite. Раздельные services/repositories/models, OpenAPI-типы, адаптер реестра ФСП. RU/EN охватывает интерфейс, API-сообщения, объяснения, письма и банк, а не только кнопки. Пользовательские тексты автоматически не переводятся. [Архитектура](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/docs/architecture.md).

**Доказательства и границы.** В сохранённой версии README заявлено 446 backend- и 124 frontend-теста. Авторские симуляции: точность грейда 82,6%; совпадение грейда при повторе всей процедуры 75,9%; тот же или соседний — 99,8%; P@5 подбора 0,880. Это результаты синтетической модели, а не измерение на реальных наймах. Экспертная калибровка, веса и пороги поведения требуют пилота; ФСП — мок; ATS в основном концепция. Числа актуального снимка отличаются от кэшированной веб-страницы README. [Отчёты](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/evaluation/results/tests_report.md), [matching report](https://github.com/miliantr/fsp-talent/blob/906a559c7ee0e0fa016a6bad411a24752e5588c2/evaluation/results/matching_report.md).

**Самое полезное:** разделение подтверждённой квалификации, соответствия вакансии и свежего сигнала; независимые движки; несколько категорий; адресное назначение задач; полноценная локализация.

## 3. LaimOr127 — развитый продуктовый цикл, паспорт и RLS

[Репозиторий](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-). Снимок: `e5958fa2cb88714d155b5fece23044967e5981ff`.

**Продукт.** Анонимный каталог по категориям, приглашение без обязательной вакансии, обязательная зарплатная вилка, просмотр/принятие/отказ/отзыв/истечение обращения. Классические отклики, собеседования и офферы. Импорт PDF/DOCX-резюме, PDF-профиль, статус поиска, отдельная видимость полей, зарплатная аналитика и рекомендации роста. Уведомления и отметки просмотра хранятся на сервере и синхронизируются между устройствами. [README](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/README.md), [matching.md](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/docs/matching.md).

**Тест.** По документации 114 параметрических шаблонов, 7 специализаций и 5 грейдов. Форма из 15 вопросов трёх соседних уровней, подбор с весами под специализацию и стек кандидата. Числовые ответы и выбор утверждения; EAP/IRT 3PL. Провал блокирует тот же и более высокие грейды на 14 дней; нижний доступен сразу. Смена подтверждённого грейда — 90 дней; уверенный результат даёт окно повышения. [assessment.md](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/docs/assessment.md).

**Задача недели.** Выбор по SHA-256 от анонимного ID и номера недели; задачи, добавленные в течение недели, преимущественно участвуют со следующей. Есть исключение: если старых задач нет, используются доступные новые. Это стабильная ротация, а не тот же персональный подбор по слабым компетенциям, что у miliantr. Ответы работодателю анонимны, их можно оценить и пригласить автора. [tasks.py](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/backend/app/services/tasks.py).

**Паспорт навыков.** Публичный подписанный снимок Ed25519, QR и проверка по ID; год действия, явный выпуск/отзыв, отзыв прежнего паспорта при выпуске нового. Различаются имя из ФСП и заявленное имя, анонимное представление и демо-стенд. Подпись подтверждает целостность снимка, а не истинность всех заявленных навыков. По отозванному паспорту проверка не возвращает содержимое. [passport.py](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/backend/app/services/passport.py), [тесты паспорта](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/backend/tests/test_passport.py).

**Подбор.** Без вакансии — тест/ФСП/актуальность с весами 60/25/15. Под вакансию — категория/тест/навыки/ФСП/описание/актуальность/формат и город/зарплата: 30/20/20/10/5/5/5/5. Подтверждённые навыки учитываются полнее заявленных. Отсутствие ФСП даёт нулевой вклад — это отличается от нейтральной базы miliantr. Описанная в документации оценка LLM даёт второе мнение по анонимным карточкам первых десяти кандидатов и не заменяет формулу ранжирования. [Механика](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/docs/matching.md).

**Архитектура.** React/Vite + FastAPI + PostgreSQL; Caddy, worker, outbox, Mailpit и отдельный fsp-mock. RLS-контекст `app.user_id`/`app.role` применяется к транзакциям; миграции включают RLS и создают политики; отдельные тесты на PostgreSQL. Есть административный контур и MFA. Это реальный код защитных механизмов, но не доказательство отсутствия обходов. [db/session.py](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/backend/app/db/session.py), [политики миграций](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/backend/migrations/rls.py), [RLS-тесты](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/backend/tests/test_rls_postgres.py).

**Границы.** Качество матчинга и теста оценено на синтетике; цифры производительности зависят от авторского стенда. ФСП демонстрационный. Много дополнительных сценариев увеличивает объём внедрения. Лицензия MIT присутствует отдельным файлом. [validation.md](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/docs/validation.md), [LICENSE](https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP-/blob/e5958fa2cb88714d155b5fece23044967e5981ff/LICENSE).

**Самое полезное:** переносимый паспорт, серверные уведомления, полный путь до собеседования/оффера, RLS и раздельные права приложения/БД, стабильная задача недели.

## 4. fazzyfan/FSP_26 — надёжная попытка и управляемый доступ к контактам

[Репозиторий](https://github.com/fazzyfan/FSP_26). Снимок: `2ddba6d314edd7e933387eb4e67878c8a7b78131`.

**Продукт.** Сквозной обратный найм; две специализации — Python backend и системный анализ, Junior/Middle. Компания описывает потребность, получает фильтруемую подборку и приглашает кандидата. [README](https://github.com/fazzyfan/FSP_26/blob/2ddba6d314edd7e933387eb4e67878c8a7b78131/README.md).

**Попытка теста.** Шесть заданий в трёх блоках, серверный таймер 20 минут, одна активная попытка. Ответы сохраняются по мере выбора и восстанавливаются после перезагрузки. Сохранение отклоняется для завершённой/просроченной попытки; переданная клиентом версия сравнивается с `answers_version`, чтобы обнаружить устаревшее обновление. Итоговый порог — 70% и минимум 50% в каждом блоке; пересдача той же категории — 24 часа, смена подтверждённой — 90 дней. Это небольшая форма с порогами, а не большой IRT-банк. [assessment.py](https://github.com/fazzyfan/FSP_26/blob/2ddba6d314edd7e933387eb4e67878c8a7b78131/backend/app/services/assessment.py).

**Контакты.** Принятие приглашения и согласие на раскрытие проверяются раздельно. Требуется активный аккаунт, статус accepted, дата согласия и отсутствие отзыва. Право относится к конкретному приглашению/компании; повтор старого принятия не должен восстанавливать отозванный доступ. Общая проверка используется для выдачи контактов и PDF. [contacts.py](https://github.com/fazzyfan/FSP_26/blob/2ddba6d314edd7e933387eb4e67878c8a7b78131/backend/app/services/contacts.py), [invitations.py](https://github.com/fazzyfan/FSP_26/blob/2ddba6d314edd7e933387eb4e67878c8a7b78131/backend/app/api/v1/invitations.py).

**Подбор и приглашения.** Формула по README: 60% компетенции, 30% тест, 10% ФСП; фильтры исключают неподходящие категории. Вилка положительна и обязательна; одно открытое приглашение от компании кандидату. Есть обработка повторов и конкурентных запросов. [matching.py](https://github.com/fazzyfan/FSP_26/blob/2ddba6d314edd7e933387eb4e67878c8a7b78131/backend/app/services/matching.py).

**Архитектура и эксплуатация.** React/Vite; FastAPI, async SQLAlchemy/asyncpg, Alembic, PostgreSQL. Серверные сессии в HttpOnly-cookie, Argon2id, CSRF, Problem Details и request_id. Версии согласий, отзыв публикации/ФСП/обработки. Приёмочные и нагрузочные скрипты, backup/restore и проверка восстановления в отдельной БД. Трассировка требований помогает проверять полноту сценария. [decisions.md](https://github.com/fazzyfan/FSP_26/blob/2ddba6d314edd7e933387eb4e67878c8a7b78131/docs/decisions.md), [requirements_trace.md](https://github.com/fazzyfan/FSP_26/blob/2ddba6d314edd7e933387eb4e67878c8a7b78131/docs/requirements_trace.md).

**Границы.** ФСП — демонстрационный адаптер, небольшой тест не обеспечивает автоматически устойчивую оценку всех технических ролей. Версионность ответов полезна, но фактическую атомарность конкурентных операций нужно проверять отдельно. Заявленная нагрузочная цель p95 ≤ 0,5 с относится к локальному стенду, здесь не воспроизводилась.

**Самое полезное:** восстановление теста, версия автосохранения, серверный дедлайн, отзыв контактов, единая политика доступа для всех способов выгрузки.

## 5. Daniel123912/invite-match — компактный Next.js + FastAPI

[Репозиторий](https://github.com/Daniel123912/invite-match). Снимок: `fe2df67f40bddc366392ebe40e3d4a2a4a87fa61`.

**Продукт и стек.** Next.js 16 + TypeScript + Tailwind, FastAPI + SQLAlchemy, PostgreSQL в Compose и SQLite локально, JWT. Кабинеты кандидата/работодателя, профиль, опрос, тест, категория, потребности и приглашения. Есть импорт/предпросмотр резюме и отзыв доступа к контактам. [README](https://github.com/Daniel123912/invite-match/blob/fe2df67f40bddc366392ebe40e3d4a2a4a87fa61/README.md).

**Механики.** В README описаны A/B-варианты теста, порог 60%, кулдаун смены грейда 90 дней и отсутствие принудительного понижения. Формула ранга в коде: `0.7 × test_score + 0.3 × min(fsp_score, 100)`. ФСП — баллы заглушки; отсутствие достижений даёт 0. Это простой и понятный базовый ранжировщик, но не аналог многокомпонентного соответствия условиям потребности. ## 9. Общая спецификация, которую стоит сохранить

Следующий список — синтез исследования для собственного решения, а не дословные требования какого-либо репозитория.

1. **Квалификация отдельно от резюме.** Заявленный и подтверждённый грейды — разные поля; стаж не определяет грейд. ФСП усиливает доказательность и позицию внутри категории, но не заменяет тест.
2. **Категория — специализация × грейд.** Допускаются несколько независимых категорий. В подборке используется категория нужной специализации, а подтверждённые общие навыки могут переноситься между направлениями.
3. **Индивидуальность без потери сопоставимости.** Шаблоны с вычисляемым ответом, план тем/сложности, версия банка/параметров, seed и снимок заданий попытки. Нельзя считать разные случайные наборы автоматически равноценными.
4. **Правила теста на сервере.** Старт создаёт попытку; ответы сохраняются; дедлайн и завершение проверяет сервер; повтор submit не меняет результат. При конфликте автосохранения нужен управляемый ответ клиенту.
5. **Неопределённость видна.** Показывать подтверждённый уровень, компетенции, уверенность и следующую допустимую попытку. Сигналы списывания ведут к проверке/подтверждающей форме, а не автоматически доказывают нечестность.
6. **Подбор измеряет соответствие.** Сначала пригодность категории, затем стек, уровень под потребность, условия, ФСП и свежесть. Более высокий грейд не всегда лучше для заданной вакансии.
7. **Объяснение следует из формулы.** Хранить вклад каждого фактора и версию весов; отличать подтверждённые данные от самоописания. Итоговый процент — индекс соответствия, пока не доказано, что он означает вероятность найма.
8. **Приглашение — самостоятельный объект.** Конкретная компания/кандидат, описание, вилка, статус, срок, защита от дублей; вакансия может быть необязательной.
9. **Контакты — отдельное право.** Согласие связано с компанией, имеет дату/версию/отзыв. Проверка едина для карточки, PDF, экспорта и интеграции. Удаление/деактивация аккаунта закрывает дальнейшую выдачу.
10. **Адресное задание полезнее случайной активности.** Потребность → рассматриваемый кандидат → слабая компетенция → объяснение назначения → срок → автопроверка или рубрика → свежий сигнал. Короткие задания не должны незаметно менять официальный грейд.
11. **Паспорт — переносимый снимок.** Подпись, версия данных, происхождение утверждений, срок действия и публичная проверка отзыва. Отдельное решение кандидата о публикации.
12. **LLM — ограниченная дополнительная функция.** Разбор текста или второе мнение по обезличенным данным; фиксированная схема ответа, бюджет/таймаут/fallback. Генерируемые моделью задания требуют проверки и калибровки до влияния на грейд.
13. **Доказательная валидация.** Test–retest, разделяющая сила заданий, эквивалентность форм, ошибки классификации, ложные сигналы нечестности; для подбора P@K/NDCG/MRR и сравнение с базовой формулой. Затем пилот на реальных данных.

Минимальная модель данных: пользователь и роли; компания/участники; профиль/приватность/согласия; категории; версия банка/шаблон; попытка/выданный вопрос/ответ; результат теста; привязка и доказательства ФСП; потребность; снимок подбора/факторы; приглашение/разрешение на контакты; задание/назначение/ответ/рубрика; уведомление/outbox; паспорт/отзыв; журнал действий.

- `archives/`: семь оригинальных ZIP остались в локальном исследовательском рабочем пространстве; в LTN не включены.
- `sources/`: распакованные снимки остались локально; пути в доказательствах обозначают исследованные файлы. Их оригиналы доступны по URL и SHA из манифеста.
- [evidence.json](evidence.json): значимые точные сниппеты, проверка покрытия индекса и результаты трассировок.
- [IDEAS_CHECKLIST.md](IDEAS_CHECKLIST.md): короткий список для планирования собственного решения.

У всех семи источников GitHub API на момент сохранения указал `fork=false`. Это характеристика исходных репозиториев; новых форков при работе не создавалось.

Лицензии: отдельный MIT LICENSE найден у LaimOr127. У Slavik993 MIT объявлена в package.json/README, отдельного LICENSE в корне нет. У PRANGATE README ссылается на отсутствующий корневой LICENSE. У остальных GitHub API вернул `license=null`, отдельного корневого текста лицензии в снимках нет. Это учёт содержимого, а не юридическое заключение о допустимости конкретного способа использования.
